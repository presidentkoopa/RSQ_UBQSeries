# RSQ Tactical Rig: findings from reading the code (2026-11-27)

Read at commit 13e1ae4b9. Every ZScript file the rig includes was read whole (`zscript.txt` and the 18 files in
`zscript/rsqtr/`), with KEYCONF, CVARINFO, MENUDEF, MAPINFO and the heads of the generated lumps (MODELDEF, RSQTRFIT,
RSQTRLAY). Nothing was run: no rig, no headset. Each finding is a question for the owner. Nothing was changed.

Paths are inside `TacticalRig/`. `rig.zs`, `cig.zs`, `body.zs`, `hooks.zs`, `keyring.zs` and `rsmenu.zs` are in
`zscript/rsqtr/`. "Old README" is the README.md this pass replaced (in git at 13e1ae4b9).

Ordered by what a player would meet first. Wording and comment mismatches are at the end.

Not a finding, but asked about: the rig has no next or previous weapon code of its own. The only place it reads those
keys is the cigarette's key handler (cig.zs:627), which ends the ritual. What next and previous cycle is decided
elsewhere (the engine, or RSQ Wheel).

## F1: An empty hand held in a holster no longer frees it while you still carry its gun
- **OWNER 2026-11-27: "Remove the hold". DONE: freeing a holster by holding an empty hand in it is taken out (rig.zs: the arming, FreeTick, its ring rule). The wheel's Clear and putting another gun in are the ways. NOT YET COMPILED OR RUN.**
- Kind: possible bug
- Where: rig.zs:2750 (the hold is armed only if the holster's gun is not "in hand or coming"), rig.zs:2847 (the same test again when the second is up), rig.zs:1786-1795 (that test is also true for a gun simply held in either hand), rig.zs:1849-1857 (a carried gun in no hand is put back into its holster after 10 tics), rig.zs:3728 (the ring is still shown as usable for this); the note at rig.zs:2747-2749
- What the code does: an empty hand pressed in an empty holster that belongs to gun X. If X is in either hand, the hold is never armed: the press is refused (double pulse) and holding does nothing. If X is carried but in no hand, the 11-27 "home" rule puts X back in the holster within 10 tics, so the press draws X. The hold frees the holster only when X is no longer carried at all.
- Why it looks wrong: the note says the guard is for a gun "on its way to a hand" (a draw that is waiting). The test also catches a gun resting in the other hand, which is the usual way to do it: gun in one hand, free its holster with the other. That worked before 11-27 and the old README still says so (its line 56). The ring still lights for that hand as if the hold would work.
- Sure?: certain about the code. Whether the tighter rule is wanted is the owner's call.
- Fix A: block the hold only while the gun is coming (a pending switch or a queued off hand raise), not while it is held (about 4 lines, 1 file).
- Fix B: retire free by hand: the new take over rule (a gun put into another gun's empty holster takes it) and the Wheel's Clear already free a holster. Remove the hold, FreeTick and the ring rule (about 30 lines, 1 file).
- Or intended: the README keeps its row: held one second, an empty hand frees only the holster of a gun you no longer carry.

- Fix A: while the main hand is at the pocket, the press is the pocket's: skip the holster press for that hand, as the throw already does (1 or 2 lines, 1 file).
- Fix B: move or shrink the pocket until the two spheres clear, measured with the place tools (1 or 2 constants, 1 file). There is little room: 5 cm lower clears the shoulder but touches the left chest holster.
- Or intended: the README adds a row: a grip high in the cigarette pocket also works the left shoulder holster.
