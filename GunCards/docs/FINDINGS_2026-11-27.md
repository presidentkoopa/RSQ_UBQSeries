# RSQ Gun Cards: findings from reading the code (2026-11-27)

Read at commit e2b60912e. Every ZScript file Gun Cards includes was read whole (zscript.txt and the files under
`zscript/rsqgc/`; of the generated data, `mcard_states.zs`, `side_states.zs` and `side_states_b.zs` only far enough to
know what they are), with CVARINFO, MENUDEF, MAPINFO, CREDITS.txt and the heads of MODELDEF, VOXELDEF and TEXTURES.
There is no KEYCONF. Nothing was run: no rig, no headset. Each finding is a question for the owner. Nothing was changed.

Paths are inside `GunCards/` unless they start with another folder. `card.zs`, `cnd.zs`, `side.zs`, `items.zs`,
`gestcopy.zs`, `handsync.zs`, `spots.zs`, `worldcard.zs`, `modelcard.zs` and `rsmenu.zs` are in `zscript/rsqgc/`.
"Old README" is `GunCards/README.md` as committed at e2b60912e (`git show e2b60912e:GunCards/README.md`).

Ordered by what a player would meet first. Wording and comment mismatches are at the end.

**The keys plan (design/KEYBINDS_PLAN.md:6) against the code:** the plan says none, and the code has none. No KEYCONF
lump, no bind matched by text, no input handler. The only buttons read are the reload buttons (Show Cards: On Reload,
card.zs:697) and each hand's fire and alt fire (Weapon Condition, to tell which hand fired, cnd.zs:596-597).

**What the code does not have at all:** a card for a gun lying on the floor, or anything that happens when a hand points
at one. Cards are made only for the weapon in each hand (card.zs:957). Grip and Use are not read. Gun Cards answers no
"my watch card is on" request: RSQ Wheel stands its own wrist card down by reading the setting `rsqgc_watch`
(Wheel/zscript/wheel/wr_q_watch.zs:59). The new README says the first under Limits. If any of these was meant to exist,
say so.

## F1: A kill by the first shot after a pause is not counted on the KILLS line
- Kind: possible bug
- Where: card.zs:141 (Track: a hand "fired" when its rounds went down, seen in WorldTick, card.zs:929); card.zs:161-165 (WorldThingDamaged gives the kill to a hand that fired in the last 35 tics); handsync.zs:23-25 (this mod's own note on the tic order: the players' input runs first, then WorldTick)
- What the code does: the hand's "fired" tic is written in WorldTick. A bullet's kill is reported while the weapon fires, which is earlier in the same tic. So for that kill the code still holds the tic of the shot before.
- Why it looks wrong: if the shot before was more than 35 tics ago (or there was none), no hand "fired" and the kill goes to no gun. A player would see KILLS stay at 0 after single shotgun or pistol kills; a shotgun fired at its own pace (about 37 tics a shot) may never count. Rapid fire counts, because the shot before is recent. Rockets count, because they land later.
- Sure?: likely. Certain about this mod's code; the engine's order is from the mod's own comment, not from a run. A rig test settles it: wait 2 seconds, kill an imp with one shotgun shell, read KILLS (Debug Log prints each counted kill).
- Fix A: at the top of the kill handler, compare each hand's rounds now with the rounds Track saw last, and stamp the hand whose count is lower (about 6 lines, 1 file).
- Fix B: stamp the hand in WorldHitscanPreFired / WorldRailgunPreFired with the engine's off-hand flag, as cnd.zs:328-343 already does for condition (about 12 lines, 1 file).
- Or intended: the README says "only kills by a gun that was already firing in the last second count".

## F2: The Weapon Condition tip says worn guns "lose accuracy and damage" and backfire "under 30"; the code differs on all three
- Kind: menu disagrees with code
- Where: MENUDEF.txt:55 (the tip); cnd.zs:125, 138, 153 (backfire chance starts in the 50 to 59 band); cnd.zs:126-127 (shotguns and chainguns gain damage from 49 down); cnd.zs:707 with no other use of `acc` (accuracy is only an answer to a pack that asks "cnd.spread")
- What the code does: a gun can BACKFIRE from condition 59 down (not for energy guns). Only MISFIRE starts under 30. Bruiser guns do more damage from 49 down. This mod never changes a gun's spread; a pack must ask for it, and nothing in this repo does.
- Why it looks wrong: a player reads "under 30" and gets a BACKFIRE toast at 55. On guns whose pack does not ask, accuracy never changes at all.
- Sure?: certain about the code. Whether BD22 VR Reloaded asks "cnd.spread" is in another repo (the cnd.zs header says it does).
- Fix A: reword the tip: "Big hits wear the guns in your hands. Worn guns hit weaker and fire slower, can backfire under 60, and turn wild under 30. Steel bits and the Boss kiosk repair them." (1 line, 1 file)
- Fix B: move the code to the tip: no backfire chance at 30 and above (9 numbers in cnd.zs Curve).
- Or intended: the README keeps the code's numbers (it does now) and the tip stays loose.
