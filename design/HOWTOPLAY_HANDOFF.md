## What exists today (checked 2026-11-27)

- **Score's Glossary** (`Score/zscript/rsscore/glossary.zs`, data `glossary_data.zs` GENERATED by
  `Score/tools/gen_glossary.py` from README.md + `combo.zs` / `combos.zs`). A `ListMenu` class: title, a row of tabs, a
  list on the left, the detail on the right, text at 1.6 for VR, Up/Down/Left/Right/Page keys, mouse clicks for a
  pointer. Its font (Score Small) is **capitals only, ASCII 32-96**. The rig can press its keys through
  `rsqsc_glossary_key` (Score/CVARINFO.txt: 1 up .. 6 page up), because the rig cannot send menu keys.
- **Score owns the help screen**: `Score/MENUDEF.txt` defines `ListMenu "ReadThisMenu" { Class "RSQSC_GlossaryMenu" }`;
  a descriptor of that name wins over the engine's ReadThisMenu class (F1 / Read This!). Only one mod can do this.
- **The series' shared menu template** (`tools/rsmenu/rsmenu_template.zs`, copied into every mod under its own prefix
  by `tools/rsmenu/gen_rsmenu.sh`; e.g. `TacticalRig/zscript/rsqtr/rsmenu.zs`). It solves exactly this problem for the
  Options menu: every pk3 carries the same code, the first loaded owns the parent menu, each mod adds its own row, a mod
  not loaded adds nothing, no mod requires another. Read its header: it documents the PROTECTED-menu merge trick,
  measured on QuestZDoom 17.3.
- **The Rig's ghost hand** (`TacticalRig/zscript/rsqtr/ghost.zs`, `RSQTR_Ghost`): a translucent copy of BD22 VR
  Reloaded's FBX hand (`models/rsq/fbx/fbx_oh_free_R.md3`) that moves from the drawn hand to a holster ring and back
  (`LOOP_TICS` 52), forcing that ring visible. Today it is a one-shot first-holster tip (`rsqtr_tip_holster`), local
  only, driven from `RSQTR_Rig.WorldTick` after `DrawMarkers`. Without the FBX hand loaded only the ring lights.
  Its pose solve is `RSQTR_HeldShow.Stand` (mirrorbody.zs).
- Every mod's README has a "How to play" section (`<a name="how-to-play">`, mostly a "Do this | What happens" table);
  Monsters and PlayLog have none. **They may be out of date.**

## The design (proposed in chat, owner agreed to the scope above)

1. **One How To Play menu; each loaded mod adds its own tab.** Use the rsmenu approach, not a new pk3 and not a hard
   dependency: a shared How To Play menu class in the template (or a sibling template), every mod carries a copy under
   its prefix, the first loaded owns `ReadThisMenu` and the How To Play row, each mod registers its pages by name
   (a Service, as the series shares everything: e.g. `RSQ<prefix>_HowToService` answering `GetString("howto.tab")`,
   `GetInt("howto.count")`, `GetString("howto.page", "", i)`). A mod not loaded has no tab. Score's tab IS the Glossary
   (open it as the tab's content, or embed its families as sub-tabs); Score stops claiming `ReadThisMenu` itself.
   The alternative (host in RSQ Accessibility, the shared-services mod) is acceptable if the template route proves
   impractical; say why in the report.
2. **Layout: Score's Glossary generalised** (tabs = mods in the Options menu's group order: Body, Hands, Reach, Game,
   see MENU_PASS_BRIEF.md; list = moves; detail = what you do / what happens / needs which other mod). VR-readable
   (1.6 scale), pointer clicks, the rig key hook. Respect RSQ Accessibility's Text Size if the Glossary does not yet.
3. **Content is generated, not hand-kept**, as gen_glossary.py does: a generator per mod (or one for all) writes each
   mod's page data from its README's How to play table **after the README has been checked against the code**.
4. **SHOW ME** (Tactical Rig first): on a move that has a body gesture (holster, draw, the off hand's draw, the watch
   check, the pulse check, the cigarette ritual, the grenade spot, the keyring, recenter torso), a "Show Me" row closes
   the menu and plays the ghost hand doing it at the real place on your body. Generalise `RSQTR_Ghost` into a player of
   named demos (a path of body-relative points + a grip pose per step), requested by name through the Rig's service
   (e.g. `RSQTR_RigService GetInt("ghost.demo", "<name>")`), so other mods' pages can ask for it and get nothing
   (the row hidden) without the Rig. Keep the first-holster tip working as it does now.

## Out-of-date READMEs: how to check them

For each mod, before generating its pages: compare its How to play rows with
- its **MENUDEF.txt / CVARINFO.txt** (option names, defaults: a README row for a removed or renamed option is wrong);
- the **code paths** the row describes (grep the action, read the handler); the code wins;
- the **latest commits** touching that mod (`git log -- <Mod>/`), including today's (2026-11-27) holster changes:
  a gun put into another gun's EMPTY holster now TAKES IT OVER (no refusal); an assigned gun in no hand returns to its
  own holster; next / prev weapon now cycles every gun, holstered or not; a thrown gun frees its holster (unless Gun
  Bonsai's Boomerang Gun); Grenade's mega blast is smaller and fits under ceilings; boss weak points 40 / 60 HP.
List every README row you corrected in the report, and fix the README in the same commit (it is the source).

## Constraints

- Only the series' mods (RSQ_*, and BD22 VR Reloaded's own VR moves if the owner asks; not by default).
- No mod requires another; everything found by name; a missing mod's tab simply is not there.
- QuestZDoom 17.3, ZScript only, no engine changes. One build for Quest and PC VR.
- Words: plain, short, no casino words (Score's rule), capitals-only font where Score's font is used.
- Menu style per MENU_PASS_BRIEF.md: short labels, nothing confusing or verbose.
- Do not change gameplay. Do not change Score's Glossary entries (only how it is opened).
