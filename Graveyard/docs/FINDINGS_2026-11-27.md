## F1: RSQ Accessibility is going, and the heartbeat's flash on the stones has no switch of its own
- Kind: other
- Where: gy_Stone.zs:439-447 (photoSafe) and its uses at :122, :302, :366, :377, :412; menudef.txt:56 (Candle Flicker), :58 (Living Stones)
- What the code does: without the class RSQA_Menu, photoSafe() is always false. Candles flicker, and on each RSQ Miniboss heartbeat (every 45 tics while a fight waits) every candle swells up to 1.6 times and every stone goes full bright.
- Why it looks wrong: once Accessibility is removed, a light-sensitive player can still turn off two of the three things this guarded: the flicker (Candle Flicker) and the colour breathing (Living Stones). The heartbeat's swell and full-bright flash have no Graveyard switch. The code reading rsqa_photosafe becomes code that can never fire.
- Sure?: certain.
- Fix A: delete photoSafe and its uses; Candle Flicker and Living Stones stay the way to calm the stones, and the heartbeat always flashes (about 8 lines, 1 file).
- Fix B: a Graveyard row "Steady Stones" (gy_steady, default Off) read where rsqa_photosafe is read now (1 cvar, 1 menu row, 3 lines).
- Fix C: let Candle Flicker off also stop the heartbeat's swell and full bright (2 lines).
- Or intended: leave it; the README's RSQ Accessibility row is deleted when Accessibility goes.

## F2: In a netgame, any player's Remove button empties every player's stored stones
- Kind: possible bug
- Where: keyconf.txt:3-4 (the buttons send network events); gy_EventHandler.zs:139-150 (handled on every machine); gy_Storage.zs:151-185 (each machine clears its own three settings)
- What the code does: a network event runs on every machine, and each machine wipes its own store (all maps for Remove All, this map for Remove Map).
- Why it looks wrong: a guest who presses Remove All Gravestones wipes the host's stones and everyone else's, on every map, from their own configs. The old README calls this m8f's design.
- Sure?: likely. Certain about the code; a two-player run settles it.
- Fix A: clear the store only on the machine of the player who pressed (event.player == consolePlayer around the clear), and take the stones off the map everywhere. The other machines keep their records and send them again at the next map start (2 lines).
- Fix B: only the host's press counts, for everyone (event.player == Net_Arbitrator) (1 line).
- Or intended: the README's limit stays as written.

## F3: The store has no limit across maps, and all of it is read at every map start and death
- Kind: other
- Where: gy_Storage.zs:62-67 (the cap is per map only); gy_Storage.zs:29-31 (all three settings parsed whenever the store is opened: gy_EventHandler.zs:43, :106, :273); gy_Storage.zs:188-197 (every record counted at every death)

- Sure?: unsure. A rig timing test with a large store settles it.
- Fix A: a total cap (for example 2000 stones, oldest first across all maps) in trimThisMap (about 10 lines, 1 file).
- Fix B: Fix A plus a slider "Stones Kept" for that cap (1 cvar, 1 menu row).
- Or intended: the README's limit as written ("no limit on how many maps").
