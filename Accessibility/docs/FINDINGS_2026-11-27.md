# RSQ Accessibility: findings from reading the code (2026-11-27)

Read at commit 7bd62b727. Every ZScript file the mod includes was read whole (zscript.txt, `zscript/rsqa_rsmenu.zs`,
`rsqa_menu.zs`, `rsqa_hand.zs`, `rsqa_core.zs`, `rsqa_qol.zs`, and `zscript/rsqg/a11y.zs`, `pose.zs`, `handsync.zs`,
`gestures.zs`), with KEYCONF, CVARINFO, MENUDEF, MAPINFO, GLDEFS and the vignette shader. In the other mods only the
lines that hear or ask this mod were read. Nothing was run: no rig, no headset. Each finding is a question for the
owner. Nothing was changed.

Paths are inside `Accessibility/` unless they start with another folder. `core.zs`, `qol.zs`, `hand.zs` are
`zscript/rsqa_*.zs`; `gestures.zs` is `zscript/rsqg/gestures.zs`. "Old README" is `Accessibility/README.md` as
committed at 7bd62b727.

Ordered by what a player would meet first. Wording and comment mismatches are at the end.

**The keys plan (design/KEYBINDS_PLAN.md:19) against the code:** the plan keeps the nine buttons, and the code has
exactly nine (KEYCONF.txt:14-22), none bound. All nine are dropped while One Handed is off (core.zs:95), which is the
default (CVARINFO.txt:15). So every key sits behind a bind nobody has and a setting that ships off.

**What the 11-27 changes did to the buttons:** none of the nine lost its hearer. Shield Throw's branch is still in
ShieldSaw/zscript/ssq/state.zs:1261-1266. The Saber's wrist twist is not something this mod touches. The Whip, Wheel
and Tactical Rig changes show up as wording here (F7) and as old README claims (F12, F13).

**What the code does not have at all:** the wrist cross as a gesture. This mod's reader has no such request
(gestures.zs:979-992). The move is read by RSQ SlowMo itself (SlowMo/zscript/rsqsm/clock.zs:2318); here it is only a
key. The gesture reader also measures nothing until a mod asks it (gestures.zs:202), so with no asking mod loaded the
Watch Check, Tick When Ready and Gesture Names rows do nothing. The new README says both under Limits.

The nine buttons, checked against the receiving code (from the reader's report). All nine are aliases for the local
event `rsqa_key <code> <down>`; all are dropped while One Handed is off (default); none is bound.

## F1: The Flick Reload key does nothing unless a saber, the Force hand or the ShieldSaw is in the off hand
- Kind: possible bug
- Where: KEYCONF.txt:21 and :34 (the key, code 7); core.zs:110 (sent as `rsqa_alt 7 1`); ShieldSaw/zscript/ssq/offflick.zs:71 and :77; QuestSaber/zscript.txt:7642 and :7648; MENUDEF.txt:164-165 (tip: "A key for the flick reload.")
- What the code does: two places hear code 7. Each reloads the main gun only while its own item is in the off hand (the ShieldSaw; a saber or the Force hand). A search of `weaponsets/` finds no `rsqa_alt` at all, so the pack whose flick reload this stands in for (weaponsets/GNRC_Reloaded/zscript/rsq/flick.zs) never hears the key.
- Why it looks wrong: a one-handed player with a gun, and nothing of the Saber or ShieldSaw in the other hand, presses Flick Reload and nothing happens. The tip promises "the flick reload" with no condition. The gun's own reload key still reloads, so the player is not stuck.
- Sure?: certain about the two hearers. An owner answer settles whether the key was meant to cover the plain two-gun flick.
- Fix A: the weapon pack's flick.zs hears `rsqa_alt 7` and enters the main gun's Reload state as its own flick does (about 8 lines, 1 file, in the weapon pack).
- Fix B: this mod does it itself: on code 7, when no Saber or ShieldSaw item is in the off hand, enter the main gun's Reload state (about 10 lines, core.zs NetworkProcess). The mod then acts on a gun for the first time.
- Or intended: the README says "only while a saber, the Force hand or the ShieldSaw is in the off hand", and the tip is reworded to match.
