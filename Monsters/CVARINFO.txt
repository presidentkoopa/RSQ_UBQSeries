// CURSES -- TWO POOLS, TWO ORIGINS, ONE CURE. Owner rulings 2026-08-07.
//
// The design in one paragraph, because it is spread across four files:
//
//   WEAPON CURSES are the five stat-locks. They come from a Cursed-tier
//   find or from Promotion. They live on the RS_Weapon instance. A
//   cursed stat is HALVED and hidden on the sheet; while any curse is on

// Chance a freshly rolled weapon arrives with a stat cursed. The Cursed
// TIER floors far higher than this in code -- that tier is not a flavour
// label, it is the tier that is definitionally cursed.

// Master switch for everything below. Off, no curse of either kind is
// ever rolled and the ledger stays empty; weapons and player alike are
// clean. Existing curses are NOT stripped by turning this off -- they
// simply stop being added to.

// --- WEAPON CURSES: the lift ---------------------------------------
// Lifting restores the stat to its PRE-CURSE value and then adds a
// bonus. The bonus escalates with how deep the stack on that stat was,
// because a stat cursed three times is a dead weapon and clearing it
// should beat anything levelling could have given you.
//
// SCALE: a damage level card gives +2..4 flat, and ALL levelling in a
// promotion cycle is capped at baseline * 1.8 (i.e. +80% total). So a
// single lift at +25% already beats a few levels, and clearing a triple
// stack (+110%) is worth more than a whole cycle of cards. That is the
// intended relationship; keep it in view if these are retuned.

// Lifting also raises the damage ceiling by the bonus it just paid.
// WITHOUT THIS, clearing a deep stack pushes damage past
// GetDamageCeiling() and the GunBonsai damage card silently stops being
// offered -- you would have spent bits to disable your own upgrades.
// The curse was suppressing the weapon's POTENTIAL, not just its number.

// One tier per lifted weapon curse, capped at Prototype.


// --- PLAYER CURSES: the death roll ----------------------------------
// Fires from RS_LifeForce.AbsorbDamage at the instant a save spends your
// LAST life, and lands on whichever hand fired most recently. 100 =
// guaranteed, which is the default because that moment should read as
// "you are out, and it cost you" rather than another dice roll.

// Also roll on saves that were NOT your last life. Off by default: the
// last-life save is the one that should mark you. Turn this up to make
// every brush with death a gamble.

// Condition lost by BOTH equipped weapons on EVERY life-save, last or
// not. Separate from the curse roll on purpose: near-death costs
// Condition (the "that hurt" tax), running out costs a curse (the
// "you're out" tax). For scale, a normal hit of 20+ raw damage already
// costs 3, and 10 Grey Bits repair 1 point -- so 10 here is 100 bits.

// Per-flaw switches. All eight ship on; a player who hates exactly one
// of these can drop it out of the pool without disabling the system.

// --- PLAYER CURSES: magnitudes --------------------------------------
// bit-repellent: the player pushes loose bits AWAY, radially. Radius in
// map units, strength in units of push per tic. Bits are ordinarily
// inert pickups; this is the only thing in the mod that moves them.

// jam-prone: percentage points added to the Condition backfire chance
// for that hand, INDEPENDENT of Condition -- a pristine weapon can jam.

// loud: the tinnitus ring. A shot starts it for this many tics; a shot
// fired while it is STILL ringing adds half again, up to maxstack times
// the base. Owner design 2026-08-07. 70 tics is two seconds.
//
// It MASKS rather than ducks -- there is no listener volume in ZScript,
// so the ring simply plays over the room, which is how this is done in
// practice anyway. Music is untouched and the player's master volume is
// never exceeded (GZDoom already scales every sound by snd_sfxvolume).

// Ceiling on the ring's own volume, percent. Deliberately not 100: a
