# RSQ Saber: findings from reading the code (2026-11-27)

Read at commit 692b3e53c (QuestSaber/ is unchanged at be048d6e1, where other mods' lines are cited). Every ZScript file
the Saber includes was read whole (zscript.txt and the four files under `zscript/`), with KEYCONF, CVARINFO, MENUDEF,
MAPINFO, DECALDEF, MODELDEF.hip, and the head of GLDEFS, SNDINFO and the generated MODELDEF. Nothing was run: no rig, no
headset. Each finding is a question for the owner. Nothing was changed.

Paths are inside `QuestSaber/` unless they start with another folder. `Z` is `zscript.txt`. "Old README" is
`QuestSaber/README.md` as committed (`git show HEAD:QuestSaber/README.md`).

Ordered by what a player would meet first. Wording and comment mismatches are at the end.

**The keys plan (design/KEYBINDS_PLAN.md:14) against the code, part by part:**
- "Saber: none": true. KEYCONF has no key section and no menu key; only `AddSlotDefault 1 UBQS_Saber` (KEYCONF:1) and
  one alias (KEYCONF:6).
- "Second Blade and Blade On / Off go": the keys are gone. Their events are still answered (`ubqs_blade2`,
  `ubqs_ignite`, Z:6683-6706) but only a typed `netevent` reaches them (F7).
- "the off-hand saber's second blade lights by TWISTING THE WRIST": true, and the off hand only (Z:909): 75 degrees
  against the roll 7 tics before, the hand at 1.2 units a tic or less, 21 tics between twists (Z:897-900, :914-915).
- "Training Remote becomes a menu button": true. MENUDEF:154 is a Command row that runs the alias `ubqs_remote_toggle`.
- Not in the plan, and read by the code: Brutal Doom's Dual button, +user3 (Z:7006, added 11-24), and the main
  saber's alt fire as its second blade when Force Push on Alt is off (Z:773-775).

**What the code does not have at all:** a way to turn the blade off; a way to take a saber from the hip without RSQ
Tactical Rig; the twirl and the joined staff (both removed; `merged` is never set); Force Speed and Force Lightning
without Gun Bonsai VR. The new README says the first two under Limits.

**Who owns the Force:** Push, Pull, Grip, the fling and the Force jump are all this mod's (`UBQS_Force`, Z:4737-5937).
Gun Bonsai VR owns only their levels and numbers, asked by name. Force Speed's slow motion is RSQ SlowMo's
(`rsm_pulse`, Z:5590).

## Owner report 2026-11-27 10:22: moving the off-hand saber to the main hand with keypresses crashes the game
"it's not supposed to move." His rule since 10-02 (zscript.txt:1233). The DoEffect code puts bOffhandWeapon back every tic

Fix (owner 10:57 "finish the saber fix"; not compiled, not run):
- The engine path (qzd17.3): `switchhand N` (double Y = 1, double B = 0) is a CCMD that calls PlayerPawn.SwitchWeaponHand(N) straight away on the console player (g_game.cpp:335-350). SwitchWeaponHand (player.zs:2488-2503) takes the weapon from the hand NOT named (0: OffhandWeapon, 1: ReadyWeapon), and only if it lacks NoHandSwitch and the player is alive: asks PickNextWeapon for the hand it leaves, sets ReadyWeapon and OffhandWeapon both to null (no psprite cleared), flips its bOffhandWeapon, makes it PendingWeapon and calls BringUpWeapon (player.zs:1926-2006: it goes into the new hand, PendingWeapon back to WP_NOCHANGE, that hand's layer set to its Select state, the layer's caller set to it, p_pspr.cpp:356); then, if the next pick is another weapon and neither is two-handed, the same for that one into the hand left. A layer left without its weapon is destroyed by TickPSprites (player.zs:551-566).
- Crash cause, from the code (not reproduced): the saber's DoEffect flips its bOffhandWeapon back the next tic (Z:1260-1261). A_Raise then picks the layer by that flag (weapons.zs:318, :329), the layer of the hand the saber is NOT in, and at the top sets the saber's Ready state on it (weapons.zs:343) while the layer's caller is the other hand's weapon. The first saber action run there is refused by the engine and the VM aborts (info.cpp:143-145, "Invalid class ... UBQS_SaberBase expected", rethrown at :240). Proven for double Y with any other main-hand weapon carried, and for double B when PickNextWeapon finds another off-hand weapon. With nothing in that hand the raise instead never finishes (GetPSprite returns null, p_pspr.cpp:335) and the hand is stuck. Which branch the owner hit, and that this abort is the crash he saw: a guess.
- Fix: `+WEAPON.NOHANDSWITCH` on UBQS_SaberBase (Z:475-491), so both sabers. SwitchWeaponHand tests it first (player.zs:2491) and does nothing at all when the weapon to be moved is a saber: no hand emptied, no flag flipped, no psprite touched, the other hand left as it was. Nothing else in the engine reads the flag (weapons.zs:99). The DoEffect pin stays for the other paths (Z:1257-1259); Z:7173-7174 notes a main-hand gun moved by double Y can still evict the second saber.
- README Limits: one line (README.md:175). ubqs_howto.zs regenerated (gen_howtoplay.py, --check clean).
